Validador de acesso à Homologação

Confirme se, com a VPN ligada, você resolve os ambientes para o servidor interno (192.168.2.32). Quando o acesso público for bloqueado, só quem resolve pelo interno continuará acessando.

⏳Testando…
Fazendo requisições aos endpoints de teste (somente VPN/local respondem).

Como funciona

Esta página faz um GET em endpoints de teste (test-vpn.<env>.sittax.com.br:8089) que só aceitam conexões internas (VPN/LAN) por geo-IP.
  • Respondeu 200 → você resolveu para o interno (.32) via VPN. ✅ Vai continuar funcionando após o bloqueio.
  • Falhou / bloqueado → você está resolvendo pelo IP público (177.223.44.35) ou sem VPN. ❌ Vai ficar sem acesso quando o público for bloqueado.
Se um ambiente responde interno, todos respondem (mesmo DNS interno). Os endpoints não servem conteúdo — só validam a origem.

Se deu ❌ — verifique no seu computador

Rode os comandos abaixo. O esperado é a URL resolver para 192.168.2.32 (interno). Se resolver para 177.223.44.35 ou um IP da Cloudflare (104.x / 172.67.x), você está no DNS público.

Windows (CMD)

ping 192.168.2.32
Resolve-DnsName stage.sittax.com.br
ipconfig /flushdns
Resolve-DnsName stage.sittax.com.br
ping 192.168.2.32
nslookup stage.sittax.com.br
ipconfig /flushdns
nslookup stage.sittax.com.br
ping -c 4 192.168.2.32
nslookup stage.sittax.com.br
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
nslookup stage.sittax.com.br
ping -c 4 192.168.2.32
getent hosts stage.sittax.com.br        # ou: nslookup stage.sittax.com.br
sudo resolvectl flush-caches            # ou: sudo systemd-resolve --flush-caches
getent hosts stage.sittax.com.br
Como interpretar:
• ping 192.168.2.32 responde → você alcança a rede interna (VPN/LAN OK).
• nslookup retorna 192.168.2.32 → DNS interno OK ✅.
• nslookup retorna 177.223.44.35 / IP Cloudflare → DNS público ❌.

Para corrigir

  1. Confirme que a VPN está conectada.
  2. Rode o flush de DNS do seu SO (comandos acima) e teste de novo.
  3. Se o ping 192.168.2.32 falhar → problema de VPN/rota (reconecte a VPN).
  4. Se o ping funciona mas o nslookup dá IP público → problema de DNS (reconecte a VPN para repegar o DNS interno; no Windows isso reaplica o block-outside-dns).
  5. Persistindo, chame a infra com o print desta página.
